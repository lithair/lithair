# Code of Conduct

Lithair is a small open-source project with a solo maintainer. The rules
below exist so that issues, pull requests, and reviews stay useful for
everyone — including future readers who land on a thread years later.

## Expected

- **Argue about code, not people.** "This breaks replay on torn tails
  because…" is useful; comments about the author are not.
- **Bring evidence.** Reproduction steps, version numbers, logs, and
  links to the relevant source beat adjectives. This matches how the
  project itself works (see `CONTRIBUTING.md`).
- **Assume competence and good faith** — in maintainers, contributors,
  and reporters alike. Most disagreements here are about trade-offs,
  not mistakes.
- **Accept the outcome.** The maintainer decides what merges. A declined
  PR or a "won't fix" with a rationale is a normal end state, not an
  invitation to escalate.

## Not accepted

- Personal attacks, insults, or harassment of any kind, in any project
  space (issues, PRs, reviews, commit messages, discussions).
- Discriminatory remarks or deliberate hostility toward any person or
  group.
- Publishing someone's private information.
- Sustained disruption: derailing threads, reopening settled decisions
  without new evidence, spam.

## Scope

This applies to all project spaces on the Lithair repositories and to
anyone participating in them — maintainer included.

## Enforcement

Report conduct issues privately via
[GitHub's private reporting](https://github.com/lithair/lithair/security/advisories/new)
— the same channel as security reports (pragmatic for a solo-maintainer
project; see `SECURITY.md`). Reports are read by the maintainer only.

Consequences scale with severity and repetition: a request to rephrase,
hidden/edited comments, locked threads, and as a last resort a block
from the project. Conduct decisions are explained briefly but are not
debated at length.
