# lithair-macros test layers

Three layers guard the macro surface. They pin **different invariants** —
refactors must not drop one because another "already covers it".

## 1. Token-level unit tests (`src/declarative_simple.rs` `#[cfg(test)]`)

Assert **what tokens the macro emits** (e.g. "clap is reached via
`::lithair_core::__private::clap`"). Fast, precise, but they compile
nothing: they cannot tell whether the emitted code actually resolves at
the call site.

## 2. trybuild compile-fail (`tests/compile_fail.rs` + `tests/ui/*.rs`)

Assert that **invalid usage fails the build with a pinned diagnostic**
(unknown keys, flags given values, attributes in the wrong position).
Refresh snapshots with `TRYBUILD=overwrite cargo test -p lithair-macros
--test compile_fail`; snapshots must be stable on the pinned toolchain
(`rust-toolchain.toml`).

## 3. End-to-end compile coverage (`examples/12-server-main-cli`)

A workspace binary whose entire `main()` is generated by
`#[server(main, cli)]`. `cargo build --workspace` (cidx build/pr phases)
compiles the full expansion on every PR.

Why it exists (issue #68): PR #67 dropped the generated
`use ... clap::Parser as _;` — token tests still passed, but the generated
`Args::parse()` no longer resolved. Later, #163 deleted the
`serve_on_port` fn the macro still emitted — again invisible to token
tests. Only compiling the expansion into a real binary catches this class
of bug, and only this crate does that (no other workspace member derives
`#[server(main, cli)]`).

Keep its dependency list minimal on purpose: the generated code must reach
clap/tokio/anyhow/serde_json through `lithair_core::__private` (issue #66),
so the example must NOT declare them directly.
